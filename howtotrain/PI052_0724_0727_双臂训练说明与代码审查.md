## 3. 两组训练的 state/action 语义

两组训练只有 state 表示不同，action 表示相同。

### 3.1 GPU1：相对 state + 相对关节 action

机械臂 state：

```text
state_arm(t) = q(t) - q(t-1)
```

首帧或前一帧为 padding 时，机械臂相对 state 置 0。

夹爪 state：

```text
state_gripper(t) = g(t)
```

机械臂 action chunk：

```text
action_arm(t,k) = q(t+k) - q(t), k=1..50
```

实际 LeRobot 索引利用 `action[t] == state[t+1]`，模型第 0 个 action token 对应 `q(t+1)-q(t)`。

夹爪 action chunk：

```text
action_gripper(t,k) = g(t+k)
```


state 和 action 使用两套独立 q01/q99，不会互相复用。两组训练的 action 统计相同。

### 4.2 统计公式

每个 14D 维度分别计算全量训练数据的 1% 和 99% 分位数：

```text
x_norm = 2 * (x - q01) / (q99 - q01) - 1
x      = (x_norm + 1) * (q99 - q01) / 2 + q01
```

当前 `clip_quantiles=false`，超出 q01/q99 的样本允许归一化到 `[-1,1]` 以外，不会被截断。反归一化仍严格使用同一套 q01/q99。

## 5. 图像输入与视觉编码

### 5.1 相机顺序

`image_feature_order` 明确设置为：

```text
1. observation.images.top
2. observation.images.gripper_left
3. observation.images.gripper_right
```

`empty_cameras=0`，因此三个输入都是数据集真实图像，没有空相机占位。metadata 中字段的存储顺序不会改变模型顺序；`PI05Config.validate_features()` 会按 `image_feature_order` 重排输入 feature。

### 5.2 图像几何处理

PI052 继承 PI05 的 OpenPI `resize_with_pad_torch`，不是 ACT 的 `camera_crop_resize_torch`。

顶部相机：

```text
405x720
-> 等比例 resize 为 126x224
-> 上下各补 49 像素黑边
-> 224x224
```

左右腕部相机：

```text
480x640
-> 等比例 resize 为 168x224
-> 上下各补 28 像素黑边
-> 224x224
```

因此当前 PI052 不执行腕部 `640x480 -> 水平中心裁剪 480x480 -> 224x224`。这是 OpenPI/PI05 的保持比例补边规则。如果部署推理端使用中心裁剪，就会与本次训练不一致；推理必须复用 PI052 preprocessor。

图像首先从 `uint8 [0,255]` 转成 `float32 [0,1]`，补边值为 0，然后转为 SigLIP 所需的 `[-1,1]`。所以模型中黑边像素值为 `-1`。

`dataset.image_transforms.enable=false` 表示没有随机图像增强，不会关闭上述固定 resize/pad。

### 5.3 视觉 token 与跨相机交互

每张图先独立经过同一个 SigLIP vision tower，得到视觉 token；随后按 top、left、right 顺序拼接进 PaliGemma prefix。SigLIP 内部不会在三张图之间交互，但拼接后的视觉 token 会在 PaliGemma prefix attention 中共同参与计算，因此模型后续存在跨相机信息交互。

### 5.4 视觉梯度检查

当前关键配置：

```text
freeze_vision_encoder=false
freeze_language_model=true
unfreeze_lm_head=false
knowledge_insulation=false
gradient_checkpointing=true
```

代码路径检查：

1. `_preprocess_images()` 读取三张真实图并生成 `mask=true`。
2. `_embed_supervised_prefix()` 在 `knowledge_insulation=false` 时不进入 `torch.no_grad()`。
3. `embed_prefix()` 调用 SigLIP `vision_tower`，视觉输出进入 flow/FAST 的共享 prefix。
4. 当前实验使用 `knowledge_insulation=false`，因此 action/flow loss 可以回传到视觉 prefix；这属于为观察视觉 action 监督而设置的实验开关，不是严格官方默认值。
5. `freeze_vision_encoder=false` 不会把 vision tower 的参数设成 `requires_grad=false`。
6. `gradient_checkpointing=true` 使用 Transformers 的 vision checkpointing API，降低激活显存，不改变梯度语义。

视觉 tower 参数保存为 float32；训练通过 Accelerate 使用 bf16 autocast。这是当前官方式 PI052 路径，没有启用此前自定义的“强制视觉全程 FP32并关闭内部 checkpoint”修改。到 step 100 的 loss 和梯度均为有限值，暂未发现视觉数值异常。

本地与远端的 PI052、processor、factory、joint representation 和 launcher 哈希一致。继承的 `modeling_pi05.py` 有一处 native-loader 之外的旧 checkpoint key remap 差异，但 PI052 设置 `use_native_pretrained_loader=true`，当前 PI052 Base 具有 437 个 `vision_tower.vision_model.*` key，训练日志无 missing/unexpected key，因此该差异不影响本次 PI052 加载。

## 6. loss 与优化器

启用的配置：

```text
flow_loss_weight=10
fast_action_loss_weight=1
text_loss_weight=1
enable_fast_action_loss=true
flow_num_repeats=5
```

总 loss 逻辑：

```text
total_loss = 10 * flow_loss + text_loss + fast_action_loss
```

数据集只有 task，没有 subtask/memory target。recipe 中缺失的 target 会跳过，因此 `text_loss_weight=1` 不代表每个 batch 一定有有效 text CE；flow loss 和 FAST action loss 仍正常提供监督。

flow loss 在归一化后的 action 上求 MSE，不先反归一化。FAST action loss对同一份归一化相对 action 进行 token 化。当前没有验证集，所以不会计算 valid loss、物理单位 MSE 或每关节 valid MSE。

优化器和 scheduler：

```text
optimizer: AdamW
peak lr: 2.5e-5
betas: [0.9, 0.95]
eps: 1e-8
weight decay: 0.01
grad clip norm: 1.0
warmup: 5000 optimizer steps
cosine decay: 100000 optimizer steps
final lr: 2.5e-6
```

日志中的 `grdn` 是裁剪前梯度范数；optimizer 更新前按 1.0 裁剪。

## 11. 最终结论与注意事项

当前两组训练的 state/action 语义、q01/q99、模型输入顺序、视觉梯度路径和 loss 计算是连贯的，没有发现后 7D 被 padding 后丢弃或 loss 只计算前 7D的问题。PI052 内部 action 会 pad 到 32D，但 flow loss 在计算后截回真实 `output_features[ACTION].shape[0] == 14`，左右双臂 14D 都参与 loss。

### KI 开关的正确解释

如果要求“严格与 PI052/OpenPI 官方语义一致”，应使用：

```text
knowledge_insulation=true
```

KI=true 的作用不是冻结视觉编码器，而是只在 action expert 查询 VLM prefix 的路径上 detach VLM 的 K/V。这样可以阻止 flow/action expert loss 反向改变 VLM 的知识路径。由于本训练还启用了 FAST action loss，FAST token CE 仍在 VLM prefix 路径上计算；只要 `freeze_vision_encoder=false`，视觉编码器仍可以从 FAST 监督得到梯度。

当前正在运行的两组任务使用 `knowledge_insulation=false`，含义是额外允许 flow/action loss 直接回传视觉 prefix。这适合“专门测试视觉是否受 action flow 监督更新”，但不应称为严格官方配置。若最终实验目标是官方可比性，应停止当前两组并从 PI052 Base 重新以 `knowledge_insulation=true` 启动，其他参数保持不变。

需要持续注意：

1. PI052 图像使用等比例缩放加黑边，不是 ACT 腕部中心裁剪；推理必须保持一致。
2. 当前没有验证集和每关节 MSE，只能用训练 loss 与实际推理结果判断。
3. 显存接近 24 GB 上限，不要直接增大 batch、flow repeats 或图像数量。
4. `knowledge_insulation` 必须保持 `false`，否则 action loss 到视觉前缀的梯度会被隔离。
5. 若未来恢复 `unfreeze_lm_head=true`，显存和 optimizer state 会明显增加，24 GB 卡大概率再次 OOM。
