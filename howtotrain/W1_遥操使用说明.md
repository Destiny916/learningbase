# W1 Pro VR 遥操使用说明

本文档针对 DexForce W1 Pro 真机，记录已验证的 VR 遥操启动、连接、操作、退出和故障检查流程。

## 1. 设备与网络角色

W1 内部有两台 Jetson Orin NX：

| 设备 | 地址 | 主要职责 |
| --- | --- | --- |
| 控制机 PC1 | `192.168.20.20` | ROS 2、EtherCAT、真机控制、VR 遥操后端、相机和 ADB monitor |
| 应用机 PC2 | `192.168.20.21` | W1 Controller、应用、视觉/语音等 |

VR 遥操的启动命令必须在 **PC1（`.20`）** 执行。代码目录为：

```bash
/home/dexforce/w1
/home/dexforce/w1/dexe_mobile_application/script
/home/dexforce/w1/dexe_teleoperate
```

## 2. 真机安全前检查

遥操会直接向机器人发布身体关节和灵巧手目标，进入页面不等于只看画面。开始前：

1. 确认机器人周围至少有约 1.5 m 的净空，现场有人可以按急停。
2. 确认没有同时运行 Auto、ACT、Map、动作回放或其他身体控制脚本。
3. 确认机器人当前没有电机错误，且反馈状态正常。
4. 第一次进入 VR 页面时先做配准，不要在配准过程中按握柄进入遥操。

可在 PC1 上查看模式：

```bash
systemctl is-active dexe-auto.service dexe-tele.service dexe-act.service dexe-map.service
```

## 3. 启动 Tele 遥操模式

在 PC1 上执行：

```bash
ssh dexforce@192.168.20.20
cd /home/dexforce/w1/dexe_mobile_application/script
./change_mode.sh tele
```

脚本会要求输入 sudo 密码，并执行以下切换：

- 停止 `dexe-auto.service`；
- 停止 `dexe-act.service` 和 `dexe-map.service`；
- 停止 ACT 容器 `act_ros2`；
- 启动 `dexe-tele.service`。

如果希望 Tele 成为重启后的默认模式，才使用：

```bash
./change_mode.sh tele start
```

`tele start` 会修改定时器启用状态，普通临时遥操不要加 `start`。

## 4. 启动后的服务验收

```bash
systemctl is-active dexe-tele.service
systemctl is-active dexe-auto.service dexe-act.service dexe-map.service
ss -lntp | grep -E ':8443\b|:8764\b|:8765\b|:8770\b|:8012\b|:8013\b'
curl -k -sS -o /dev/null -w 'HTTPS_8443=%{http_code}\n' \
  --max-time 5 https://127.0.0.1:8443/
```

正常结果应为：

```text
dexe-tele.service  active
auto/act/map        inactive
HTTPS_8443=200
```

Tele 后端主要包含 pose server、robot view server、HTTPS 前端、头/腕相机服务和 ADB monitor。

## 5. Quest 头显连接方式

Quest 3S 必须作为 USB 数据设备被 **PC1 `.20`** 识别。仅在本机插入头显而没有把 ADB 链路接到 PC1，不能驱动 W1。

在 PC1 检查：

```bash
lsusb | grep -Ei '2833|oculus|meta|quest|pico'
adb devices -l
adb reverse --list
```

已验证的 Quest 3S 设备会显示类似：

```text
2833:5013 Oculus VR, Inc. Quest 3S
<serial> device ... model:Quest_3S
```

遥操所需反向端口由 `scripts/adb_monitor.py` 自动建立：

```text
8764  姿态服务
8012  相机服务
8443  HTTPS 控制界面
8765  机器人视图
8770  W1/底盘控制
8013  头/腕相机 WebSocket
8864  低频数据
8788  辅助服务
```

如果 `adb devices` 为空：

1. 唤醒并解锁 Quest；
2. 使用支持数据传输的 USB 线；
3. 尽量绕过 USB Hub，直接接 PC1；
4. 在头显弹出的 USB 调试确认框中选择允许；
5. 重新检查 `adb devices -l` 和 `adb reverse --list`。

## 6. 打开遥操界面

### 6.1 Quest 头显

头显已通过 ADB reverse 连接到 PC1 时，在 Quest 浏览器打开：

```text
https://localhost:8443/
```

### 6.2 普通电脑浏览器

从能访问机器人控制网段的电脑打开：

```text
https://192.168.20.20:8443/
```

这是自签名 HTTPS，浏览器可能显示证书风险，需要手动选择继续访问。不要把该端口直接暴露到公网。

## 7. VR 页面内操作

1. 选择穿戴式/头戴式模式并完成配准。
2. 确认虚拟机器人姿态与真机反馈一致。
3. **双手同时按住握柄键**进入遥操。
4. 松开任意一侧握柄退出遥操，并令底盘停止。
5. 左摇杆控制底盘移动；`B` 切换 parking/differential 底盘模式。
6. `Y` 在无故障时切换腿部模式；有电机错误时先清错。
7. `X/A` 切换左右手势，扳机控制抓握。
8. 头戴模式下，在未遥操、未录制时长按 `X+A` 约 3 秒返回模式选择。

数据链路为：

```text
WebXR/Quest → 姿态服务 → 全身 IK/重定向 → 重心与自碰撞检查
→ /control/joint_position 和手部控制话题 → W1 真机
```

## 8. 遥操期间的数据采集

在 VR 遥操页面中：

- 单击左摇杆：开始录制；再次单击：停止录制；
- 连续双击右摇杆：删除上一段录制，此操作不可恢复；
- 停止后等待相机保存完成，再切换模式或拔线。

默认数据位置（PC1）：

```text
/home/dexforce/w1/dexe_teleoperate/data/raw/vr_messages_*.jsonl
/home/dexforce/w1/dexe_teleoperate/data/recorded/<session>/
```

一个 session 通常包含：

```text
pose_record_<session>.json
head/left/*.jpg
head/right/*.jpg
hand/left/*.jpg
hand/right/*.jpg
metadata.jsonl
```

录制后应检查四路图像是否可解码、各路帧数、时间戳单调性、pose 是否为 20D，以及相机与姿态时间差。不要覆盖原始数据。

## 9. 停止遥操

先在 VR 中松开握柄，确认机器人和底盘停止，再退出页面。然后在 PC1 执行：

```bash
cd /home/dexforce/w1/dexe_mobile_application/script
./change_mode.sh auto
```

该命令会停止 Tele 并启动 Auto。若只需要停止 Tele、暂时不启动其他模式，应由现场人员确认底层机器人服务仍在运行且没有控制发布者后再处理，不能直接杀掉底层 `robot_server`。

## 10. 典型故障诊断

### 10.1 服务 active，但 Quest 进不去

先检查：

```bash
systemctl is-active dexe-tele.service
adb devices -l
adb reverse --list
ss -lntp | grep -E ':8443\b|:8764\b|:8765\b|:8770\b'
```

如果服务和端口正常但 Quest 页面打不开，检查证书：

```bash
openssl s_client -connect 127.0.0.1:8443 </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

本次检查发现 W1 当前 HTTPS 证书位于：

```text
/home/dexforce/w1/dexe_teleoperate/src/backend/core/configs/certs/
```

该证书已于 `2026-01-27` 过期，日志会出现 `SSLV3_ALERT_CERTIFICATE_UNKNOWN`。需要由维护人员重新生成/替换证书后重启 `dexe-tele.service`；不要通过关闭 TLS 或把服务暴露到公网来规避。

### 10.2 端口显示 open，但没有动作

端口可达不代表已经进入遥操。确认：

- Quest 页面已完成配准；
- 双手同时按住握柄；
- 没有其他 `/control/joint_position` 发布者；
- 真机反馈状态为 `Idle`/正常，电机状态为 `OP`，错误码为 `0`。

查看身体控制源：

```bash
source /opt/ros/humble/setup.bash
source /home/dexforce/w1/install/setup.bash
ros2 topic info /control/joint_position -v
timeout 5 ros2 topic hz /control/joint_position
```

### 10.3 退出或切换模式后手臂姿势异常

先停止 Tele/Auto 等控制源，再使用官方目标文件恢复，避免同时发布：

```bash
cd /home/dexforce/w1/dexe_mobile_application/script
python3 slowly_move_to.py records.d/default/rest.json 1500
```

`rest.json` 是 W1 的低位/蹲下默认身体姿势；`standby.json` 是站立 Standby 姿势。动作前必须确认现场安全，并在反馈中核对 20D 目标误差和电机错误码。

## 11. 关键安全边界

- 不要同时启动 Tele、Auto、ACT、Map 或自定义动作脚本。
- 不要把 `adb reverse` 端口映射误认为已经进入遥操；必须看到 Quest 页面连接和实际控制数据。
- 不要在手臂姿势异常时继续按握柄；先退出遥操并恢复安全姿势。
- 任何身体动作都应以实际 `/feedback/joint` 和 `/feedback/robot_server_state` 为验收依据。
- 结束遥操后先松握柄、确认停止，再退出页面和切换服务。
