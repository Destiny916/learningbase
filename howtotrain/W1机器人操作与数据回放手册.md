# W1 Pro 机器人操作、拖拽、遥操与数据回放手册

本文档记录当前 W1 Pro 的实际操作方法。命令执行前请先确认所在机器：

| 设备 | 地址 | 主要职责 |
|---|---:|---|
| PC1（控制机） | `192.168.20.20` | EtherCAT、ROS 2、机器人运动、Tele、ACT/VLA、数据采集 |
| PC2（应用机） | `192.168.20.21` | W1 Controller、界面、应用配置、视觉/语音 |
| 本机 XWiz | 当前 `192.168.20.164` | XWiz 界面、模型部署和推理接口 |

## 1. 安全原则

1. 机器人运动前确认周围无人、无障碍物，先读取关节反馈和机器人状态。
2. `/control/joint_position` 同一时间只能有一个运动控制源。不要同时运行 Auto、ACT、Tele、拖拽和手动回放。
3. 进入拖拽前停止自动控制；退出拖拽后再切换 Auto/Tele。
4. 回放前先恢复到第一帧，确认机器人姿态和安全空间，再开始整段回放。
5. 停止运动优先停止控制服务/进程，不要直接断电或拔 EtherCAT 线。

## 2. 模式切换（PC1）

```bash
ssh dexforce@192.168.20.20
cd /home/dexforce/w1/dexe_mobile_application/script
```

查看模式：

```bash
./change_mode.sh status
```

切换到 Tele 遥操：

```bash
./change_mode.sh tele
```

切换到 Auto：

```bash
./change_mode.sh auto
```

停止 Tele/Auto 后，应检查：

```bash
systemctl is-active dexe-tele.service
systemctl is-active dexe-auto.service
ps -eo pid,stat,args | grep -Ei 'policy_bridge|policy_infer|tele_mode' | grep -v grep
```

Tele Web 界面：`https://192.168.20.20:8443`。实际 VR 遥操还需要头显通过 ADB 接入 PC1；仅启动 Tele 服务并不代表头显已经连接。

## 3. 拖拽模式

拖拽模式允许直接用手推动机器人，底层服务会降低/解除部分控制约束。必须先停止 Auto、ACT、Tele 等运动源。

开启拖拽（PC1，ROS 2 域为 20）：

```bash
export ROS_DOMAIN_ID=20
source /opt/ros/humble/setup.bash
source /home/dexforce/w1/install/setup.bash
ros2 service call /control/set_property robot_server_interfaces/srv/SetProperty \
  "{property_type: EnableDrag, value: 'true'}"
```

关闭拖拽：

```bash
ros2 service call /control/set_property robot_server_interfaces/srv/SetProperty \
  "{property_type: EnableDrag, value: 'false'}"
```

服务返回 `request_id` 表示请求已被控制服务接受。关闭拖拽后再启动 Auto 或 Tele。

## 4. 固定姿态和指定位置

固定姿态文件位于 PC1：

```text
/home/dexforce/w1/dexe_mobile_application/script/records.d/
```

常用默认姿态：

```text
act_default_pose_runtime.json       ACT 模型默认姿态
records.d/default/standby.json      站立 Standby 默认姿态
records.d/default/rest.json         蹲下/休息默认姿态
```

三种姿态不等价。ACT 真机推理启动门禁要求 `act_default_pose_runtime.json`；
站立和蹲姿用于普通待机/收纳。从真机模型推理或部署停止后，不应自动猜测
返回哪一个；先询问操作者选择 ACT 默认、站立默认或蹲姿默认，再执行对应
的低速插值。

将机器人低速移动到指定 JSON 的第一帧：

```bash
cd /home/dexforce/w1/dexe_mobile_application/script
export ROS_DOMAIN_ID=20
source /opt/ros/humble/setup.bash
source /home/dexforce/w1/install/setup.bash
python3 slowly_move_to.py records.d/default/rest.json 1500
```

最后一个参数是插值点数；`1500` 约 30 秒，数值越大动作越慢。该工具会读取 `/feedback/joint`，比较关节名称，并向 `/control/joint_position` 发布插值命令；没有关节反馈时不会开始移动。

若要移动到自定义位置，JSON 至少需要以下结构：

```json
{
  "frames": [
    {"frame": 0, "timestamp": 0, "data": {
      "ANKLE": 1.35,
      "KNEE": -2.7,
      "BUTTOCK": 1.35,
      "WAIST": 0.0,
      "NECK1": 0.0,
      "NECK2": 0.0,
      "LEFT_J1": 0.0,
      "RIGHT_J1": 0.0
    }}
  ]
}
```

实际使用时应提供完整的 20 个身体关节；灵巧手目标通过 `/control/ee/left` 和 `/control/ee/right` 发布。

## 5. Tele 遥操

1. 确认机器人处于安全姿态，停止 Auto/ACT。
2. 在 PC1 执行 `./change_mode.sh tele`。
3. 打开 `https://192.168.20.20:8443`。
4. 确认头显已连接到 PC1 的 ADB；如果头显在本机而非 PC1，Tele 后端无法收到 VR 输入。
5. 操作前先小幅移动控制器，观察机器人反馈，再进行大动作。
6. 结束时退出录制、停止 Tele，并恢复安全姿态。

## 8. 回放动作

### 8.1 先恢复到第一帧

`pose_record_*.json` 的第一帧位于 `frames[0]`。回放前必须先停止 Tele/Auto，并把第一帧作为目标做低速插值。身体关节可使用 `slowly_move_to.py`；该工具要求手部字段使用 `LEFT_HAND_*`/`RIGHT_HAND_*` 命名，需要将记录中的 `LEFT_T_MCP` 等字段映射到对应名称。

恢复完成后检查 `/feedback/joint` 与第一帧的误差，确认机器人已经停在第一帧。

### 8.2 按原始时间回放整段动作

姿态记录的 `frames` 数组包含 `timestamp` 和 `data`。回放程序应：

1. 读取 `pose_record_*.json`；
2. 以第一帧时间戳为零点，按相邻帧时间差等待；
3. 向 `/control/joint_position` 发布 20 个身体关节；
4. 同步向 `/control/ee/left`、`/control/ee/right` 发布手部目标；
5. 回放结束后停止发布并保留最后一帧。

本机/PC1 上已有调试命令回放工具，可用于 `teleop_debug_*.jsonl` 中的 `command` 事件：

```bash
cd /home/dexforce/w1/dexe_teleoperate
export ROS_DOMAIN_ID=20
source /opt/ros/humble/setup.bash
source /home/dexforce/w1/install/setup.bash
python3 scripts/tools/replay_cmd_from_debug.py \
  data/debug/teleop_debug_YYYYMMDD_HHMMSS.jsonl --rate 1.0
```

该工具会直接控制真实机器人；`--rate 1.0` 为原速，`--rate 0.5` 为半速。`pose_record_*.json` 需要使用按上述规则读取姿态帧的回放程序，不能直接当作 debug JSONL 传给该工具。

### 8.3 回放验收

回放后比较最后一帧目标与 `/feedback/joint`：

```bash
ros2 topic echo /feedback/joint --once
```

同时确认：

```bash
systemctl is-active dexe-tele.service
systemctl is-active dexe-auto.service
ps -eo pid,stat,args | grep -Ei 'policy_bridge|policy_infer' | grep -v grep
```

```bash

```


## 10. 常见问题

- **XWiz 报 `librmw_cyclonedds_cpp.so` 找不到**：确认已安装 `ros-jazzy-rmw-cyclonedds-cpp`，并检查 `~/xwiz/config/ros2.env` 的 `ROS2_PREFIX=/opt/ros/jazzy`。
- **看不到机器人话题**：确认本机地址、`ROS_DOMAIN_ID=20`、CycloneDDS 网卡地址和机器人网线均正确。
- **回放无动作**：先检查 `/feedback/joint` 是否有 publisher，再检查是否有 Auto/Tele/policy 进程占用控制话题。
- **手部没有动作**：确认记录包含手部字段，并检查 `/control/ee/left`、`/control/ee/right` 的消息类型和订阅者。
- **拔掉网线后失联**：当前 PC1/PC2 只有有线 LAN 接口；XWiz 本机也需要保持与机器人同一网络或配置其他网络链路。
