# 双臂遥操与数据采集

真机：`kw@192.168.10.82`。数据采集逻辑以 [temp2.md](/home/wengyikun/workplace/joint_songling/temp2.md) 为唯一来源，不使用旧的 sensor 双击采集流程。

## 固定 CAN 映射

```text
USB 1-1.4.1.4:1.0 -> left_piper  -> 左机械臂
USB 1-1.4.2:1.0   -> right_piper -> 右机械臂
```

不要依据临时接口名 `can0`、`can1` 判断左右。USB 扩展坞重置后，必须重新运行：

```bash
cd /home/kw/workspace/pika_ros/src/PikaAnyArm/piper/piper_ros
sudo bash ./can_config.sh

ip -details link show left_piper
ip -details link show right_piper
timeout 5 candump -L left_piper right_piper
```

只有两路均为 `UP / ERROR-ACTIVE / 1000000`，并且 `candump` 能持续收到左右反馈帧，才能继续遥操。

## 启动遥操

确认双臂上电、工作空间内没有人或障碍物。以下四个终端按顺序执行。

### 终端 A：夹爪与夹爪相机

不使用鱼眼，保留左右 RealSense RGB 与深度图。

```bash
conda deactivate
source /opt/ros/humble/setup.bash
source ~/workspace/pika_ros/install/setup.bash

cd ~/workspace/pika_ros/scripts/
bash start_multi_gripper.bash gripper sensor --no-fisheye
```

### 终端 B：Pika 定位与 sensor

不使用 sensor 深度和鱼眼。

```bash
conda deactivate
source /opt/ros/humble/setup.bash
source ~/workspace/pika_ros/install/setup.bash

cd ~/workspace/pika_ros/scripts/
bash start_multi_sensor.bash sensor --no-fisheye --no-depth
```

确认定位已经发布：

```bash
ros2 topic echo /pika_pose_l --once
ros2 topic echo /pika_pose_r --once
```

### 终端 C：双臂遥操节点

```bash
conda deactivate
source /opt/ros/humble/setup.bash
source ~/workspace/pika_ros/install/setup.bash

export PATH=/opt/openrobots/bin:$PATH
export PKG_CONFIG_PATH=/opt/openrobots/lib/pkgconfig:${PKG_CONFIG_PATH:-}
export LD_LIBRARY_PATH=/opt/openrobots/lib:${LD_LIBRARY_PATH:-}
export PYTHONPATH=/opt/openrobots/lib/python3.10/site-packages:${PYTHONPATH:-}

cd ~/workspace/pika_ros/scripts/
ros2 launch pika_remote_piper teleop_rand_multi_piper.launch.py
```

### 终端 D：使能与状态监控

首次动作前在安全姿态下发布一次使能：

```bash
conda deactivate
source /opt/ros/humble/setup.bash
source ~/workspace/pika_ros/install/setup.bash

ros2 topic pub --once /enable_flag std_msgs/msg/Bool "{data: true}"
```

分别观察左右遥操状态：

```bash
ros2 topic echo /teleop_status_l
```

```bash
ros2 topic echo /teleop_status_r
```

左右 sensor 的双击只用于原有的左右遥操开始/结束；它不控制数据采集。首次使用时，应分别测试物理左、右 sensor 是否使对应状态变化。若左右不对应，检查 sensor trigger 映射，不要交换 CAN 左右映射。

## 数据采集

采集前必须完成上述 CAN、夹爪、定位和遥操启动。采集内容为：

```text
双臂关节与夹爪状态
双臂 FK EE 位姿
左右 Pika 位姿与 sensor 夹爪状态
左右夹爪 RealSense RGB 与对齐深度图
左右双目 RGB 图像
```

不采集顶部相机或鱼眼相机。

### 启动空格采集器

采集器由 [temp2.md](/home/wengyikun/workplace/joint_songling/temp2.md) 的 Bash 代码块生成并运行。它会先检查所有必要 ROS 话题，再启动双目拆分、capture worker 与常驻 service client。

在新的前台终端执行：

```bash
export DATASET=YOUR_DATASET_NAME
export DATA_ROOT=/home/kw/workspace/lerobot_wyk_dev/data

awk '
  /^```bash$/ { block = 1; next }
  block && /^```$/ { exit }
  block { print }
' /home/wengyikun/workplace/joint_songling/temp2.md > /tmp/spacebar_capture.sh

bash /tmp/spacebar_capture.sh
```

成功后终端显示类似：

```text
IDLE: dataset=/home/kw/workspace/lerobot_wyk_dev/data/<DATASET>, next episode=<N>
SPACE=start/end episode, q=finalize and quit
```

采集状态和按键含义：

| 当前状态 | 按键 | 结果 |
| --- | --- | --- |
| `IDLE` | `Space` | 创建并开始下一个 `episode<N>`。 |
| `RECORDING` | `Space` | 结束并保存当前 episode，回到 `IDLE`。 |
| `IDLE` 或 `RECORDING` | `q` | 若正在采集则先完成落盘，然后只停止采集基础设施。 |

采集器始终常驻在此终端。必须让该终端处于键盘焦点；按下键盘空格或 USB 开关映射出的空格，才会触发采集。

### 使用 USB 开关触发空格

确认 USB 开关已被系统识别后，在另一终端运行：

```bash
sudo -E env \
  DISPLAY="${DISPLAY:-:0}" \
  XAUTHORITY="${XAUTHORITY:-$HOME/.Xauthority}" \
  PYTHONPATH="$HOME/.local/lib/python3.10/site-packages" \
  python3 /home/kw/bin/usb_switch_space.py
```

脚本只把一次开关按下转换成一次空格，不会发送 CAN 或 ROS 控制指令。若出现 `USB switch 2704:2018 was not found`，先检查扩展坞或重新插拔开关；不要把普通键盘设备替代为开关。

### 数据保存位置与日志

每个 episode 保存到：

```text
/home/kw/workspace/lerobot_wyk_dev/data/${DATASET}/episode<N>
```

日志保存在：

```text
/home/kw/workspace/pika_ros/runs/latest/
```

常用日志：

```bash
tail -f /home/kw/workspace/pika_ros/runs/latest/data_capture_${DATASET}_spacebar.log
tail -f /home/kw/workspace/pika_ros/runs/latest/stereo_split_${DATASET}_spacebar.log
```

## 关闭顺序

1. 在采集器前台终端按 `q`，等待显示 `Capture infrastructure stopped.`。
2. 结束遥操终端中的 `ros2 launch`。
3. 再结束 sensor 和 gripper 终端。

如果 CAN/USB 扩展坞在运行中重置，停止遥操后重新执行 CAN 配置与反馈检查，再重新启动受影响的 ROS 节点。

## 快速故障检查

| 现象 | 处理 |
| --- | --- |
| `left_piper`/`right_piper` 不存在或为 `DOWN` | 重新运行 `can_config.sh`，并用 `candump` 确认反馈。 |
| `/pika_pose_l` 或 `/pika_pose_r` 无数据 | 处理定位后再启动遥操，不要直接使能。 |
| capture 启动失败 | 查看 `data_capture_<DATASET>_spacebar.log`；该脚本会逐一报出缺失话题。 |
| 双目图像缺失 | 查看 `stereo_split_<DATASET>_spacebar.log`，确认 `/stereo/left/color/image_raw` 和 `/stereo/right/color/image_raw` 都有数据。 |
| 要开始/结束 episode | 仅在采集器的前台终端按 `Space`，不是双击 sensor。 |
